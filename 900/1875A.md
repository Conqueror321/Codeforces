# Codeforces 1875A - Jellyfish and Undertale

## Problem Idea

We have a bomb timer.

- `a` is the maximum possible timer value.
- `b` is the initial timer value.
- `n` is the number of tools.
- Tool `i` increases the current timer `c` to `min(c + x_i, a)`.

Every second, the timer decreases by `1`. We want to maximize the total time before the bomb explodes.

## Key Observation

It is always optimal to use a tool when the timer is equal to `1`.

Why?

If the current timer is `c`, after using a tool with value `x_i`, the timer becomes:

```text
min(c + x_i, a)
```

The bigger `c` is, the easier it is to hit the upper limit `a` and waste part of the tool.

So using tools at `c = 1` loses the least possible value. There is no advantage in using a tool earlier.

## Contribution of One Tool

Suppose the current timer is `1`, and we use a tool with value `x`.

First, the timer becomes:

```text
min(1 + x, a)
```

Then the current second passes, so the timer decreases by `1`:

```text
min(1 + x, a) - 1
```

This is exactly:

```text
min(x, a - 1)
```

So one tool adds `min(x, a - 1)` useful seconds.

This is the main detail. A large tool does not add `a` seconds. It can add at most `a - 1` seconds, because we use it at timer `1` and the same second still consumes one unit of time.

## Formula

The initial timer already gives us `b` seconds.

Each tool `x_i` adds:

```text
min(x_i, a - 1)
```

Therefore, the answer is:

```text
b + sum(min(x_i, a - 1))
```

## Example

Input:

```text
1
5 1 2
100 100
```

Each tool can add at most:

```text
a - 1 = 4
```

So the answer is:

```text
b + 4 + 4 = 1 + 4 + 4 = 9
```

Manual check:

```text
1s: use tool, 1 -> 5 -> 4
2s: 4 -> 3
3s: 3 -> 2
4s: 2 -> 1
5s: use tool, 1 -> 5 -> 4
6s: 4 -> 3
7s: 3 -> 2
8s: 2 -> 1
9s: 1 -> 0
```

Total time: `9`.

## Complexity

For each test case, we only iterate over the tools once.

```text
Time Complexity: O(n)
Memory Complexity: O(1)
```

Use `long long`, because the answer can be large.
